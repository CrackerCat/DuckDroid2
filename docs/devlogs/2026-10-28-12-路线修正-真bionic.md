# 2026-10-28 路线修正：放弃纯虚拟 bionic，改为加载真实 libc.so

> 状态：**决策已定，实现待下次会话**（本文件先于代码落地）。
> 取代：`2026-10-27-01-架构评审结论.md` 第 66 行"必须明确不加载真实 libc.so"。
> 依据：同目录 `DuckDroid`（相邻项目）的 S6 已完成真实 bionic，代码可搬。

---

## 1. 问题

M4 按原路线完成了"虚拟 bionic"：`libc/liblog/libdl/libm` 是纯符号表 + host stub，
不读文件（`2026-10-28-11-M4结果.md`）。

提出质疑：既然能直接加载 bionic 的 `libc.so` 并跑它，为什么还要自己模拟？

结论：**原判断不成立，改走真实 bionic。** 下面是数据和理由。

---

## 2. 证据

### 2.1 真实目标需要多少导入符号

| 目标 | 未定义导入 | 依赖 | 说明 |
|---|---|---|---|
| `libeleven.so` | **126** | libc, libm, libdl, liblog | 346 JUMP_SLOT + 148 GLOB_DAT + 1065 RELATIVE；**无 TLS 重定位** |
| `libsgmainso-6.8.260704.so` | **166** | libc, libm, libdl, liblog, **libz.so** | section header 被人为破坏，只能用 program header 加载 |

当前虚拟表覆盖 **6 个**符号（`__errno/write/malloc/free/pthread_once/log_print`）。

`libsgmainso` 的依赖里出现 **libz.so**（`inflate/deflate/crc32`）。libz 不是 libc，
虚拟方案只能去加载真 libz.so，而 libz 自己又导入 libc —— 虚拟只在依赖图恰好是
`{libc, liblog, libm, libdl}` 时成立，真实目标从来不是。

### 2.2 真实 libc 的规模（`DuckEmu/bionic/libc.so`）

- 1.0 MB，**1479** 个动态符号
- 自身 514 个 `JUMP_SLOT`（导入 `ld-android.so`/`libdl.so`）、1016 个 `RELATIVE`、
  1 个 `TLS_TPREL64`、7 条 init_array
- NEEDED：`ld-android.so`、`libdl.so`

### 2.3 TLS 不是虚拟方案省下来的成本

- 目标自己的 `__thread` 要 `PT_TLS` + `TLSDESC` 描述符 + guest resolver 桩 + DTV；
- 真 libc 自己也用 TLS；
- **两条路写的是同一份代码**。M4 已经把 TLS 整条推迟了（clang 的 android target 只产
  `TLSDESC`），这笔账迟早要还 —— 还的时候顺带让 libc 也受益。
- 注意：`libeleven.so` 自身没有 TLS 重定位，但真 libc 有，所以加载真 libc 必须做 TLS。

### 2.4 DuckDroid 已经证明可行

`DuckDroid` 的 S6（2026-10-25）交付：加载 ROM 的真 `libc.so`/`libm.so`，跑通
`__libc_preinit`、真 scudo malloc、真 `pthread_create/join`、真 libc 的文件 I/O 与
`/proc`、dl 虚拟化。规模：

| 文件 | 行数 | 内容 |
|---|---|---|
| `engine/os/os_state.cpp` | 1904 | 128 个 syscall case、线程表、TLS/errno、VFS |
| `engine/runtime/runtime_instance.cpp` | 3629 | clone/futex/调度、`libc_shared_globals`、preinit、dl |
| `engine/loader/elf_loader.cpp` | 1278 | PT_TLS、TLS_*、IFUNC/IRELATIVE、符号作用域 |
| `engine/runtime/address_space.cpp` | 471 | 惰性物化、TBI alias |

**成本是固定的，而且已经付过一次。**

### 2.5 反向证据及其边界

S6 文档记录：真实目标 `libeleven` 在"虚拟 bionic 版 DuckEmu"和"真 libc 版 DuckDroid"
下 **100/100 逐值一致**。说明**对那个目标**虚拟层够用。

但这只覆盖"算法 + 字符串/内存 + 少量 IO"这一类。一旦目标碰 libc 内部
（TLS、`/proc/self/maps`、malloc 布局、pthread 同步、locale/宽字符），虚拟层就要
逐个补，且错了很难看出来 —— 见 §2.1 的两个真实目标。

---

## 3. 决策

1. **加载真实 bionic**：`libc.so`/`libm.so`/`libdl.so`/`libz.so` 等来自 ROM，
   走 loader 正常加载，不再由虚拟模块顶替。
2. **虚拟模块表收缩**到"真机上也不是 libc 提供的"那部分：
   - `dlopen/dlsym/dlerror/dl_iterate_phdr`（真机是 linker 提供）
   - `__system_property_get`（真机是 init/property 服务）
   - `__loader_*`（真机是 linker 提供）
   - JNI（M5）
3. **TLS 与 IFUNC 立即补齐**，不再推迟。
4. **绑定 ROM**：`libc_shared_globals` 的字段偏移按具体 ROM 的 libc 用 objdump 核对，
   换 ROM 必须重新核对。签名器场景可接受。

---

## 4. 新的里程碑切分

M4 之后的阶段重排（M5/M6/M7 编号不变，中间插入 M4.5 / M4.6）：

### M4.5 loader 补全

目标：能把真 libc 完整映射并完成所有重定位（**不执行**）。

交付：

- 打包重定位：`DT_ANDROID_RELA`（APS2/SLEB128 流）与 `DT_RELR` 位图
- `PT_TLS` + `R_AARCH64_TLS_TPREL64/DTPMOD/DTPOFF` + `TLSDESC`（描述符 + resolver 桩页）
- `STT_GNU_IFUNC` / `R_AARCH64_IRELATIVE`（resolver 在 guest 里执行）
- 真 `DT_NEEDED` 递归（libz 这类从 ROM 目录加载，不再只查虚拟表）

Gate `04b_libc_map`：

- 加载 `DuckEmu/bionic/libc.so` + `libm.so` + `libdl.so`，全部重定位成功、无未解析符号
- ModuleEvent 里能看到真实依赖边；加载 `libsgmainso`（section header 损坏）不报错

搬运来源：`DuckDroid/code/engine/loader/{elf_loader,tls_layout}.*`

### M4.6 真 libc 跑起来

目标：libc 的 preinit/init_array 执行完，malloc/pthread/文件 IO 可用。

交付（按子步骤）：

1. **syscall 面**：搬 `os_state` 的 `HandleDirectSyscall`（128 个 case），arm64 语义
2. **VFS + `/proc`**：`/proc/self/maps`、`/proc/self/status`、只读文件 mmap
3. **bionic 启动**：`libc_shared_globals`（auxv/StaticTlsLayout/tls_modules/progname/
   environ，按 ROM objdump 核对偏移）、`__loader_*` 绑定、`__libc_preinit`、init_array
4. **scudo**：8.25 GiB `PROT_NONE|MAP_NORESERVE` 预留只登记、按需物化、
   `1<<56`/`2<<56` TBI alias
5. **线程**：clone/futex 语义对齐 bionic（`pthread_create/join` 真跑）

Gate `04c_bionic`：

- 真 libc 加载 + preinit 完成；`malloc/calloc/free` 走真 scudo
- 真 `pthread_create/join` 计数正确，每线程 errno/TLS 隔离
- 真实目标 `libeleven` 的 `JNI_OnLoad` 之前的部分能跑

搬运来源：`DuckDroid/code/engine/os/os_state.*`、`runtime/runtime_instance.cpp`、
`runtime/address_space.*`

### M5 之后的调整

- M5（JNI）不变，但 JNIEnv 现在要能和真 libc 共存（`Call*Method` 仍用 M4 已落的
  `HostCallArgs::call_guest` 嵌套路径）。
- M6 验收改用真 libc 环境跑北极星 so，与 DuckDroid 的结果对拍。
- 已有 golden：`libeleven` 100/100（虚拟版与真 libc 版一致），可作回归基线。

## 5. 代价与风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| 绑定 ROM | globals 偏移与 libc 版本强相关 | 偏移集中在一处，换 ROM 时 objdump 重新核对；profile 记录版本 |
| syscall 面全有或全无 | 缺一个 syscall，libc 启动直接死 | 用 DuckDroid 的 128 个 case 起步；未实现调用沿用 M2 的栈 dump |
| 确定性下降 | malloc/时间/随机来自真代码 | 注入时钟/随机（S5 的做法）；profile 固定 |
| 依赖链变长 | libz/libssl 等要一起加载 | loader 本来就要做；这也是虚拟方案躲不掉的 |
| 与现有 M4 代码的关系 | 虚拟模块代码不白写 | `ModuleEvent`、loader 骨架、thunk、`call_guest` 全部保留；虚拟表缩成 import stub |

---

## 6. 保留 / 删除清单

**保留**

- `loader/elf/`、`module_registry`、`symbol_lookup`、`reloc_applier` 骨架、`ModuleEvent`
- thunk 页与 `HostCallArgs`（真 libc 加载后，剩余的 import stub 仍走这条）
- `RuntimeInstance::loadLibrary/lookupSymbol` 公开接口（签名不变）
- `04_so_load`、`elf_image_test`（虚拟路径仍要测试，作为 import stub 的回归）

**删除/收缩**

- 虚拟表里的 `write/malloc/free/pthread_once/__errno`（改由真 libc 提供）
- `04_so_load` 中"libc/liblog 必须是 virtual"的断言（改为"来自文件"或保留为
  import-stub 专项测试）
