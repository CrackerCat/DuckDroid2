# TLS / DTV 完整语义：静态槽、动态槽、generation 与 dlsym

> 日期：2026-10-30
> 起点：M4.5 只做了静态 TLS，M4.6 的 `tls_modules` 是空表；`PT_TLS` 全部按静态槽处理，
> TLSDESC 只用静态 resolver，`__tls_get_addr` 的 DTV 路径没有真实表可走。
> 本轮把 bionic linker 的 TLS/DTV 语义补完整。
> gate：`04n_tls_dtv`；全量 **46/46**（`build` / `build-werror` / `build-asan`）。
>
> 写法综合自两版旧实现：
> - DuckDroid S6：`code/engine/loader/tls_layout.*`、`code/engine/os/os_state.cpp`
>   的每线程 DTV 槽与 `.tdata` 复制；
> - DuckEmu M7：`docs/sub_docs/progress/2026-10-22-13-m7-tls-infrastructure.md`
>   的最小 DTV、静态 TLSDESC 与 IFUNC 顺序；
> - 语义以 ROM `bionic`（`private/bionic_elf_tls.h`、`linker/linker_tls.cpp`、
>   `libc/bionic/bionic_elf_tls.cpp`、`linker/arch/arm64/tlsdesc_resolver.S`）为准。

## 1. 语义基线（bionic / arm64 / Android 13–14）

### 1.1 三张表

| 结构 | 字段（LP64） | 作用 |
|---|---|---|
| `StaticTlsLayout` | `offset_`、`alignment_`、`overflowed_`、`offset_bionic_tcb_`、`offset_bionic_tls_` | 每线程静态块的固定布局 |
| `TlsModules` | `generation`、`generation_libc_so`、`rwlock`(56B)、`module_count`、`static_module_count`、`module_table`、回调 | 进程级模块表 |
| `TlsModule` | `segment{size, alignment, init_ptr, init_size}`、`static_offset`、`first_generation`、`soinfo_ptr` | 单模块记录 |
| `TlsDtv` | `count`、`next`、`generation`、`modules[]` | 每线程动态向量 |

`libc_shared_globals` 里 `static_tls_layout` 在 `0x450`（`0x28` 字节），
`tls_modules` 紧随其后在 `0x478`：

```text
0x478  tls_modules.generation
0x480  tls_modules.generation_libc_so
0x488  tls_modules.rwlock                (pthread_rwlock_t, 56 B)
0x4C0  tls_modules.module_count
0x4C8  tls_modules.static_module_count
0x4D0  tls_modules.module_table
0x4D8  on_creation_cb
0x4E0  on_destruction_cb
0x4E8  first_thread_exit_callback
0x4F0  thread_exit_callback_tail_node
0x4F8  tls_allocator                     (BionicAllocator, 0x120 B)
0x618  load_hook
0x620  unload_hook
0x628  set_target_sdk_version_hook       (M4.6 已核对)
```

`0x4F8 + 0x120 = 0x618`，再往后到已核对的 `0x628`，说明
`TlsModules` 的 56 字节 rwlock 与整块偏移是自洽的。ROM bootstrap `libc.so`
的反汇编也直接命中这些地址：`0x4C0`（module_count）、`0x4C8`
（static_module_count）、`0x4D0`（module_table）、`0x4D8/0x4E0`
（两个回调）、`0x4F8`（tls_allocator）。

### 1.2 模块 id 与 generation

- 第一个 TLS 模块的 id 是 **1**，`module_table[id - 1]` 是它的记录；id 0 保留给
  DTV 的第一个字（generation）和未解析弱符号。
- `TlsModules.generation` 初值 `kTlsGenerationFirst = 1`；**每次注册模块**都
  `++generation`，并把新值同时写入 libc 的 `__libc_tls_generation_copy`
  （`generation_libc_so` 在 preinit 时指向它）。
- 模块记录的 `first_generation` 是它注册时的 generation。DTV 用这个值判断
  “这个槽是本代之后才需要的”。

### 1.3 静态 vs 动态

分界线不是 `DF_STATIC_TLS`，而是 linker 的 `g_static_tls_finished`：

```text
linker 启动：加载可执行文件与 DT_NEEDED 闭包
  -> register_soinfo_tls()：static_offset = layout.reserve_solib_segment(...)
linker_finalize_static_tls()：static_module_count = module_count
之后的 dlopen：static_offset = SIZE_MAX，走 DTV 动态分配
```

静态模块的 `static_offset` 是**块内偏移**；TP 相对偏移是
`static_offset - offset_thread_pointer()`（本实现 `offset_bionic_tcb_ = 0`，
`offset_thread_pointer() = 16`）。动态模块的块在首次访问时由
`__tls_get_addr` 从 `tls_allocator` 分配，并按 `init_ptr/init_size` 复制镜像。

### 1.4 线程创建

`pthread_create` → `__allocate_thread_mapping` 按
`StaticTlsLayout.size()` 预留静态块 → `__init_static_tls(static_tls)` 遍历
`TlsModules`，把每个 `static_offset != SIZE_MAX` 的模块的 `init_size` 字节
从 `init_ptr` 复制到 `static_tls + static_offset` → `__init_tcb` /
`__init_tcb_dtv`。DTV 初始是 libc 里的 `zero_dtv`，第一次动态访问才分配。

主线程更特殊：preinit 的 `__libc_init_main_thread_final()` 用同一份
`StaticTlsLayout` 重新 `mmap` 一个最终块，`__init_static_tls` 后再
`copy_from_bootstrap` 并 `__set_tls`。因此 **主线程的最终 TLS 不是
TlsManager 的 bootstrap 块**。

### 1.5 三种 TLS 重定位

| 类型 | 值 | 语义 |
|---|---|---|
| `R_AARCH64_TLS_TPREL` | 1030 | initial-exec；模块必须有静态槽，否则 link 报错 |
| `R_AARCH64_TLS_DTPMOD` / `DTPREL` | 1028 / 1029 | general-dynamic；写 module_id 与 `st_value + addend` |
| `TLSDESC` | 1031 | 描述符 `{func, arg}`；静态 `{resolver_static, tpoff}`，动态 `{resolver_dynamic, &TlsDynamicResolverArg}` |

`TlsDynamicResolverArg = { generation, TlsIndex{module_id, offset} }`。
bionic 的 arm64 `tlsdesc_resolver_dynamic` 快路径：

```text
x20 = [TP]              // &dtv->generation
x21 = [x20]             // 当前 DTV generation
x22 = [arg]             // 模块 first_generation
if x21 < x22 -> slow
x21 = [x20 + module_id*8]   // 注意 id 从 1 起，正好跳过 generation 字
if null -> slow
return x21 + offset      // 调用方再加 TP
```

慢路径调 `__tls_get_addr(&index)`，由 libc 的 `update_tls_dtv()` 处理
DTV 扩容、旧槽释放、静态槽回填和新模块分配。

### 1.6 dlsym 的 TLS 规则

`dlsym(handle, "tls_var")` 在 bionic 里返回**当前线程的地址**，不是
`module.base + st_value`：

```text
tls_block = get_tls_block_for_this_thread(tls_module, should_alloc=true)
result = tls_block + sym->st_value
```

静态模块直接取 `TP + tls_offset + st_value`；动态模块要先确保本线程的
DTV 槽存在。

## 2. 与两版旧实现的关系

| 版本 | 已做 | 缺 |
|---|---|---|
| DuckDroid S6 | 每线程 DTV 模块槽、`.tdata` 复制到所有线程、静态 TLSDESC | 表是空骨架；所有模块静态；无 generation 增长 |
| DuckEmu M7 | bionic TCB 槽、最小 DTV（generation=`SIZE_MAX`）、静态 TLSDESC、IFUNC | `__tls_get_addr`/DTV 扩容、`tls_modules` 真表 |
| DuckDroid2 之前 | 静态槽、静态 TLSDESC、主线程 materialize | `tls_modules` 空、新线程不复制镜像、dlopen 后 TLS 语义错误 |

本轮保留前两版的形状（TCB 布局、每线程 DTV 槽、`static_offset` 与
`first_generation`），把“表”和“增长”补成 bionic 真语义。

## 3. 本次实现

### 3.1 guest `TlsModules` 表

`loader/bionic/shared_globals.{hpp,cpp}`：

- `initialize()` 把 `generation` 写成 1，映射 64 项 `TlsModule` 表并发布
  `module_count/static_module_count/module_table`；`tls_allocator` 位于同块，
  保持零初始化（constexpr 构造）。
- `addTlsModule(id, spec, is_static)`：按 id 顺序写条目、`++generation`、
  同步 `generation_libc_so`；静态条目要求全部排在动态条目前。
- `finalizeStaticTls()`：`static_module_count = module_count`，对应
  `linker_finalize_static_tls()`。
- `abandonTlsModule(id)`：加载失败时保留 id 位置与 `static_offset`，把
  `size/init_size/first_generation/soinfo` 清零。这样静态前缀仍然连续，
  `__init_static_tls` 会跳过它，DTV 也不会为它分配块。

### 3.2 loader 的静态/动态分界

`ModuleLoader::loadImage()`：

- `PT_TLS` 模块在映射成功后、重定位之前注册；`init_ptr = base + PT_TLS.p_vaddr`
  （不是文件偏移 `p_offset`），`init_size = p_filesz`。
- `static_tls_finished_ == false`：`TlsLayout::reserve()` 分配静态槽，
  `static_offset = tls_offset + 16`，并继续 materialize 到 TlsManager 的
  bootstrap 块（只影响 libc 接管前的主线程）。
- `static_tls_finished_ == true`：`static_offset = SIZE_MAX`，不再 materialize；
  等 DTV 慢路径按需分配。
- `finalizeStaticTls()` 由 `finalizeStaticTlsIfReady()` 触发：实例里出现真实的
  `__tls_get_addr`（即 ROM libc 已加载并重定位）时关闭静态前缀并发布
  `StaticTlsLayout`。`loadLibrary()` 与 guest 的 `dlopen`（`Impl::open()`）
  共用这条路径，所以 dlopen 首次拉进 libc 时也会在 preinit 之前发布布局。
  虚拟 libc / 纯 fixture 测试因此保持“全程静态”。
- 加载失败路径（依赖缺失、重定位失败、`phdr` 映射失败）调用
  `abandonTlsModule()`，避免表里留下指向已 unmap 模块的 `init_ptr`。

### 3.3 重定位

`loader/reloc/reloc_applier.cpp`：

- `TPREL`：owner 是动态模块时按 bionic 报
  `TLS symbol in dlopened ... using the initial-exec model`，不再用 0 偏移
  拼出一个坏地址。
- 弱未定义 TLS 与 bionic 对齐：`TPREL`/`DTPREL` 写 addend（`&weak_tls == TP +
  addend`），`DTPMOD` 写 0，`TLSDESC` 走 weak resolver。
- `TLSDESC`：静态 owner 仍写 `{resolver_static, tpoff}`；动态 owner 在
  `[loader] tlsdesc-args` 页里分配 24 字节
  `{generation, module_id, st_value + addend}`，描述符写
  `{dynamic_resolver, arg}`。参数页按页增长。

### 3.4 动态 resolver 与 DTV

`RuntimeInstance::Impl::resolveDynamicTls()` 是 `tlsdesc_resolver_dynamic`
的宿主 thunk（`ThunkTable` 的 `svc #imm; ret` 槽）：

1. 从 `x0 = &descriptor` 读 `arg`，再从 `arg` 读 generation/module_id/offset；
2. 用 `HostCallArgs.thread_pointer` 读 `[TP] → &dtv->generation`，比较
   `current >= module_first_generation` 且 `modules[id] != null`，命中就直接
   返回 `module_ptr + offset - TP`（TP 相对值）；
3. 否则嵌套调用 libc 的 `__tls_get_addr(arg + 8)`。`update_tls_dtv()` 会扩容
   DTV、回填静态槽、释放已卸载模块并分配新模块块，再把绝对地址减 TP 返回。

每条宿主 stub 只改 x0，x1–x17 与向量寄存器由 SVC 分发器原样保留，满足
TLSDESC resolver 的寄存器约定。

### 3.5 dlsym 的 STT_TLS

`DlService::symbol()` 现在接收调用线程的 TP 与 `call_guest`；
`ModuleLoader::lookupResolved/lookupGlobalResolved` 保留 `ResolvedSymbol.type`
与 `st_value`。遇到 `STT_TLS`：

- 静态模块：`TP + tls_offset + st_value`；
- 动态模块：先查 DTV 快路径；槽不存在时把 `TlsIndex{module_id, st_value}`
  写进 scratch 页，嵌套调 `__tls_get_addr`（等价 bionic 的
  `should_alloc=true`）。

普通符号仍返回 `module.base + st_value`；虚拟模块的 dlsym 不变。

### 3.6 启动顺序

```text
RuntimeInstance::create
  -> BionicGlobals: generation=1, empty TlsModule table
  -> TlsManager: bootstrap TCB/bionic_tls/DTV（0x10000）
  -> loadLibrary(libc): 映射 -> 注册 libc 的 PT_TLS -> 依赖闭包
       -> finalizeStaticTls()（发现 __tls_get_addr）
       -> 发布 StaticTlsLayout（真实 paddedSize，不是整块 0x10000）
       -> libc preinit: __libc_init_main_thread_final 分配最终块并复制镜像
  -> loadLibrary(app so): static_tls_finished_ == true -> 动态槽
```

## 4. 验证

`04n_tls_dtv`（两个独立实例）：

| 场景 | 断言 |
|---|---|
| 静态：先加载带 `DT_NEEDED libc.so` 的 fixture，再加载 ROM libc，同一图内 finalize | 主线程 `__thread` 初值 7；真 `pthread_create` 线程看到 7、写入 9、主线程仍 11；dlsym(STT_TLS) 读写同一副本 |
| 动态：先加载 libc 再加载 fixture | 主线程首次访问懒分配得到 7；pthread 线程独立 7009；另一 TLS 模块在 worker 停住时由宿主加载，worker 恢复后首次访问走 DTV 慢路径并看到 7；同线程两个模块互不干扰（11 / 7） |
| dlsym | `dlsym(RTLD_DEFAULT, "g_dtv_tls")` 返回当前线程副本，经指针写入后 `dtv_get` 同步变化 |

回归：`01`–`04m`、`05`、`06`、`07` 全部通过；`ctest` **46/46**；
`DUCKEMU_WARNINGS_AS_ERRORS=ON` 全绿；ASan/UBSan 下
`04b_tlsdesc`、`04b_libc_map`、`04c_globals`、`04c_preinit`、`04c_bionic`、
`04n_tls_dtv` 全绿。

## 5. 已知限制

- **没有 dlclose 卸载**：`DlService::close` 仍是 no-op，模块表条目不会
  `unregister`，DTV 也不会因卸载而收缩；线程退出时由 libc 的
  `__free_dynamic_tls()` 回收动态块。
- **表上限 64 个 TLS 模块**；每个动态 TLSDESC 参数页 170 条，满后按页增长。
- **静态边界是“首次加载真实 libc”**，不是真正的可执行文件图。纯虚拟
  libc/无 libc 的测试保持全静态；真实服务路径（先加载 ROM libc）与 bionic
  行为一致。
- **`__loader_add_thread_local_dtor` 仍是返回桩**：没有卸载，因此它本来的
  “阻止 dlclose 带 TLS 析构的模块”语义没有可观察差异。
- **`tls_allocator` 的回调字段保持 null**：`on_creation_cb` /
  `on_destruction_cb` 只有 `sys_thread_properties` 一类调试设施会设置，
  当前不使用。
- **符号版本仍被忽略**；TLS 符号的版本化解析与普通符号同一套规则。
- **16 KiB 页设备**未覆盖；静态布局按 4 KiB 页对齐验证。
