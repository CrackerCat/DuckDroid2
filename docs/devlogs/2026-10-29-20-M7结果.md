## 3. 与 DuckDroid 的对拍结论

DuckDroid 的 `libeleven_case` runner 没有时钟注入参数（其 `Profile::wall_time_ns`
必须由调用方设置），所以它输出的是宿主时钟。两边的 `n:` 段逐值一致；时间戳段按构造
不同。若要时间戳逐值相等，需要在参考 runner 上加一个 `--wall-time-ns` 参数
（一行解析 + `profile.wall_time_ns = value`），或改用 DuckDroid 的 Signer
（它已经支持 `base_wall_time_ns`）。

## 4. 已知限制

| 项 | 现状 | 何时处理 |
|---|---|---|
| prewarm < instances | v1 取 `prewarm = instances`，启动全部拉起 | 需要按需扩容时 |
| 无健康 worker 时的新连接 | System 直接关闭，客户端重连 | Web API 接入时按重试语义处理 |
| 连接数上限 / 全局背压 | 每连接一线程，无上限 | 压测后 |
| SIGTERM 优雅退出 | System 只有 `stop()`，未接 signalfd | 部署时 |
| trace 目录 | 多实例共用同一 `--trace` 目录，文件命名未按实例隔离 | 排查真实目标时 |
| MemoryPool / PrimordialProcess | 延后（进程隔离已覆盖 VA 隔离） | 需要再省内存/启动时间时 |
| 跨 Worker 会话路由 | 未做；连接亲和失效时靠 `new_session` 重试 | 多 worker 扩容时 |

## 5. 发现并修复的旧 bug（手工启动时）

- `ModuleLoader::loadImage` 的依赖加载失败路径先 `registry_.erase()` 销毁
  Module，随后又用 `registered.soname` 和循环引用 `needed`（指向已销毁对象）
  构造错误消息。ASan 报 `heap-use-after-free`；普通构建表现为实例 init 阶段
  `std::length_error` / `std::bad_alloc` 后 `std::terminate`。
- 触发条件：某个模块的 `DT_NEEDED` 在搜索路径里找不到。此前测试没有覆盖
  这条失败路径。
- 修复：错误消息在 erase 之前构造（TLS 分支同样处理）。
- 回归测试 `module_missing_dep_test`：把 `liba.so` 的 `DT_NEEDED libb.so`
  字节替换为 `libx.so`，断言 `loadLibrary` 返回 NotFound 而不是崩溃。

## 6. 手工启动

```bash
cd /home/duck/NewCode/Android/environment/DuckDroid2
ROM=/home/duck/NewCode/Android/environment/ROM/out/target/product/lemonade/symbols/system/lib64
SO=$PWD/code/user_code/libeleven_case/assets/libeleven.so

./build/duckemu_system \
  --socket-dir /tmp/duckemu \
  --worker-exec "$PWD/build/duckemu_worker" \
  --wall-time-ns 1792886400000000000 \
  --app "id=libeleven,library=$SO,rom-libc=$ROM/bootstrap/libc.so,library-path=$ROM/bootstrap:$ROM,instances=2"
```

另一个终端（第一条打开会话，第二条钉在同一实例）：

```bash
python3 code/tools/sign_client/sign_client.py /tmp/duckemu/libeleven.sock 7
# instance=...  signature=YL0uYLyRroI8Yo4Wco4W  decoded=7:1792886400000  meta={...}
# instance=...  signature=YL0uYLyRroI8Yo4Wco4u  decoded=7:1792886400001  meta={...}
```

`signature=` 是 guest 返回的原始签名结果；`decoded=` 只是 libeleven 附加的可读解释
（`custom_b64("n:now_ms")`）。`--raw` 关掉解释，`--json` 打印完整响应帧。

注意 `library-path` 的两项：ROM 目录本身就是 `.../symbols/system/lib64`，
不要再拼一次 `/lib64`。
