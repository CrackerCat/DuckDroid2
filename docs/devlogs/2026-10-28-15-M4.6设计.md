## 1. 启动顺序

真 Android 的 libc 启动是 libc 自己的 `constructor(1)`：

```text
linker 完成重定位
  -> libc.so 的 init_array[0] = __libc_preinit
       __stack_chk_guard = TLS[slot 5]
       __libc_init_globals()      // __libc_globals 清零 + mprotect
       __libc_init_common()       // environ/progname/pthread_internal_add/properties
       __libc_init_scudo()
       __libc_init_malloc()
       ...
```

因此 M4.6 的开关是 `RuntimeConfig::run_module_initializers = true`（M4.5 已加），
不需要手工调用 `__libc_preinit`。`constructor(1)` 保证它排在所有其他构造器之前。

`__libc_shared_globals()` 在 libc 里只是 `__loader_shared_globals()` 的转发
（`libc_init_dynamic.cpp:176`）。所以这个结构由我们（虚拟 `ld-android.so`）提供。

## 2. `libc_shared_globals` 布局（ROM bootstrap/libc.so 实测）

反汇编依据：

| 偏移 | 字段 | 证据 |
|---|---|---|
| `0x418` | `auxv` | `getauxval` 0x85500: `ldr x8, [x0, #0x418]` |
| `0x450` | `static_tls_layout` | 0x6e890: `ldr x9, [x0, #0x450]` |
| `0x478` | `tls_modules.generation` | preinit 0x56ea8: `add x8, x0, #0x478` |
| `0x480` | `tls_modules.generation_libc_so` | preinit 0x56eac: `str x9, [x0, #0x480]` |
| `0x628` | `set_target_sdk_version_hook` | preinit 0x56f1c: `str x8, [x0, #0x628]` |
| `0x630` | `init_progname` | init_common 0x6a3f8: `ldr x9, [x0, #0x630]` |
| `0x638` | `init_environ` | init_common 0x6a3e4: `ldr x9, [x0, #0x638]` |

`static_tls_layout` 子字段（`bionic_elf_tls.h`，arm64）：

```text
+0x00 offset_                 static TLS 总大小
+0x08 alignment_
+0x10 overflowed_ (bool)
+0x18 offset_bionic_tcb_      = 0（M1 布局 TCB 在块首）
+0x20 offset_bionic_tls_      = 0x200（M1 layout）
```

`offset_thread_pointer() = offset_bionic_tcb_ + 16 = 0x10`，与 M1/M4.5 的 TP 一致。

`tls_modules.generation` 先写 `~0ULL`（与 DuckDroid 一致）；preinit 会把它复制到
libc 自己的 `__libc_tls_generation_copy`。

块大小 0x1000，按页对齐，放在 guest heap（`RuntimeMemory::map`）。

## 3. auxv

按 DuckDroid 的同一组（顺序即内核顺序）：

```text
AT_SYSINFO_EHDR=0, AT_HWCAP=0, AT_PAGESZ=0x1000, AT_CLKTCK=100,
AT_PHDR=0, AT_PHENT=56, AT_PHNUM=0, AT_BASE=0, AT_ENTRY=0,
AT_UID/EUID/GID/EGID=1000, AT_SECURE=0, AT_RANDOM=<16B>, AT_HWCAP2=0,
AT_EXECFN=<progname>, AT_NULL
```

`AT_RANDOM` 同时用于 `__stack_chk_guard`。hwcap 置 0：guest CPU 不宣告可选扩展，
IFUNC 与 libc 的字符串实现都走通用路径（与 M4.5 的 resolver 参数一致）。

## 4. 子步骤与测试

| 步骤 | 内容 | 测试 |
|---|---|---|
| S1 | `__loader_shared_globals` 真实现 + auxv/progname/environ 块 | `04c_globals`：加载 ROM libc，调用 `getauxval(AT_PAGESZ)` == 0x1000、`getauxval(AT_EXECFN)` 指向 progname |
| S2 | syscall 面：按类别搬 DuckDroid `os_state`（内存/文件/时间/信号/线程/misc） | `04c_syscalls`：逐个 syscall 的成功/errno 断言 |
| S3 | VFS + `/proc/self/{maps,status,auxv}`、只读文件 mmap | `04c_vfs`：libc 读 `/proc/self/maps` 成功 |
| S4 | scudo：8.25 GiB `PROT_NONE\|MAP_NORESERVE` 只登记、按需物化、TBI alias | `04c_preinit`：preinit 完成，`malloc/calloc/free` 走真 scudo |
| S5 | clone/futex 对齐 bionic，真 `pthread_create/join` | `04c_bionic`（主 gate）：pthread 计数、errno/TLS 隔离、libeleven 的 JNI_OnLoad 之前部分 |

S1 可独立落地；S2/S3/S4 有依赖（preinit 会同时用到 mmap、mprotect、openat/read、
getrandom、pthread 接口），实现时按“先让 preinit 往下走一步”推进，每步提交。

## 6. 不做 / 已知限制

- 信号投递只留 no-op，不实现完整语义
- `dlopen/dlclose` 运行期装载不做（M6 前）
- 多实例隔离、warm pool 不做（M7）
- ROM 绑定后换 ROM 必须重新核对 §2 的偏移
- preinit 里的 `__system_properties_init` 允许失败（property 服务不存在），
  错误路径要能被观测到；目标是 malloc/pthread 可用，不是完整 Android 环境
