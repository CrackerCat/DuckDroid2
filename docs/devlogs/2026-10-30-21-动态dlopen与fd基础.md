# 动态 dlopen 与 fd 基础：接入下一个目标前的两处硬缺口

> 日期：2026-10-30
> 起点：M7 已过，下一目标（快手/抖音）接入前的缺口审计，按影响排序
> 建议顺序 4 → 5 → 1 → 6 → 3 的前两项。

## 1. 为什么先做这两项

审计里 4（`__loader_dlopen` 是返回 0 的桩）和 5（dup/fcntl 全缺）是
最可能让新目标**连初始化都过不去**的两处：

- SDK 惯用 `dlopen` 运行时加载子库（加固壳、特征库、风控 so 常见），
  桩返回 0 等于直接失败；
- 反调试常把 `/proc/self/maps` 的 fd `dup` 一份、或先 `fcntl` 检查
  可读性再读，缺这两组 syscall 会走失败分支。

## 2. `__loader_dl*` 接上真实实现

ld-android.so 的 8 个入口点从"绑定用、返回 0"变成真实实现：

| 入口 | 行为 |
|---|---|
| `__loader_dlopen` / `__loader_android_dlopen_ext` | 走 `ModuleLoader::loadByName`：含 `/` 按路径，否则按请求模块目录 + 搜索路径；已加载 soname 直接返回原 handle |
| `__loader_dlsym` / `__loader_dlvsym` | handle 0 / `dlopen(NULL)` 的哨兵值查全局，否则限定模块；版本段忽略 |
| `__loader_dlerror` | 每个实例一个 guest 字符串槽，读一次即清 |
| `__loader_dlclose` | 不建模引用计数，模块存活到实例结束 |
| `__loader_dladdr` | 填 `Dl_info`（路径、基址、最近的符号及地址） |
| `__loader_dl_iterate_phdr` | 按加载序回调 `struct dl_phdr_info`，带真实 `dlpi_phdr`/`dlpi_phnum` |

关键约束与解法：

- **重入**：stub 在 SVC 里执行，此时本线程正持有执行锁并处于
  `uc_emu_start` 内，`scheduler->callFunction`（投递给主线程）不可用。
  构造器、IFUNC 解析一律走 `HostCallArgs::call_guest` 的嵌套帧，
  `RuntimeInstance::Impl::open` 直接把 `call_guest` 透传下去。
- **构造器时序**：dlopen 返回前必须跑完新模块及其依赖的
  `DT_INIT`/`DT_INIT_ARRAY`；失败路径与 `loadLibrary` 一致，丢弃
  半加载图里挂起的构造器。`JNI_OnLoad` **不**在 dlopen 里调用。
- **接口归属**：新增 `loader::DlService`，由 `RuntimeInstance::Impl`
  实现并通过 `ModuleLoader::setDlService` 注入 `VirtualBionic`。
  ld-android 的其余符号仍是返回 0 的桩，绑定面不变。
- **phdr**：`ElfImage` 保留原始 program header 表，加载时映射一份只读
  guest 拷贝（`Module::phdr/phnum`），供 `dl_iterate_phdr` 使用。
- **静态 TLS**：dlopen 带 PT_TLS 的模块时 `TlsManager::materialize`
  会做越界检查；线程块放不下就按 bionic 的语义失败，而不是写坏内存。

## 3. fd 表：共享文件描述

- `FdTable` 从 `unique_ptr<File>` 改为 `shared_ptr<File>`，dup 语义
  （共享偏移）由此落地；新增 `insertShared` / `assign` / `shared`。
- 新增 `StdioFile`：0/1/2 仍走 syscall 快路径，但 `dup(1)` 会物化一个
  指向宿主 fd 的描述，`write(dup(1), …)` 照样到宿主 stdout。
- syscall：`dup`(23)、`dup3`(24)、`fcntl`(25)。
  `fcntl` 覆盖 `F_GETFD/F_SETFD/F_GETFL/F_SETFL/F_DUPFD/
  F_DUPFD_CLOEXEC/F_GETLK/F_SETLK(W)`；锁一律回"已获得"，无锁管理器。
- 已知取舍：`dup2/dup3` 目标落在 0/1/2 时返回 `EBADF`——宿主 stdio 由
  编号寻址，替换它需要 stdio 槽间接层，等有真实目标需要再补。

## 4. 测试

| 测试 | 覆盖 |
|---|---|
| `04d_dlopen` | guest 调 `__loader_dlopen` 加载插件，构造器在返回前跑完；重复打开同 handle；`dlsym` 缺失留一次性 `dlerror`；`dlclose` 不卸载 |
| `04e_dup_fcntl` | 裸 syscall：dup/dup3/F_DUPFD、共享偏移（lseek 一侧另一侧同步）、关闭后 EBADF、dup(1) 写宿主 stdout |

全量 **36/36** 通过（原 34 项无回归）。

## 5. 下一步（审计里的 1 → 6 → 3）

1. **VFS 写**：per-instance 可写沙箱根 + 覆盖语义（写根优先、
   回落到只读根）、`O_CREAT/O_TRUNC/O_APPEND`、`unlinkat/renameat/
   fsync/ftruncate`，写文件 stat 的 uid/mtime 用注入时钟与设备画像伪造。
2. **事件循环**：`poll/ppoll/select/epoll_* /eventfd2/timerfd_create`，
   阻塞点接到 `PendingSyscall`（线程挂起 + 唤醒），自管道 + poll 的
   检测/网络线程才走得通。
3. **DeviceProfile**：把散在 `szstone_env.cpp`、快照文件里的设备值收成
   一份配置（model/brand/fingerprint/CPU/屏幕/android_id/serial/uid/
   progname），统一喂属性、uname、`/proc` 合成、Settings.Secure、
   stat 元数据、`AT_RANDOM/AT_HWCAP`。真机取值可用已插入的小米 8 经
   adb 采。
