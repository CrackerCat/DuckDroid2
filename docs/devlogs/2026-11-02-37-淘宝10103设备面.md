# 淘宝 10103/10104 设备面与 JNI 反射补齐

> 日期：2026-11-02
> 触发：淘宝 `--init` 进入 10103/10104 后，SecurityGuard 的设备采集线程大量
> JNI missing（首轮 101 条）。
> 材料：旧 DuckDroid 案例 `logs/hook_a.log`、同一 APK 的 dex（jadx）。

## 1. 现象与定位

- `10102 -> 0`、`10101 -> 0`；`10103`（securitybody 插件加载通知）之后，
  native 与后台线程开始按固定清单解析 Android 类/方法/字段。
- 新增 `DUCKEMU_JNI_TRACE=1`：打印每次成功 Java 调用与字段读写（含字符串参数、
  接收者）。配合 `--jni-events`（只报失败）即可得到
  `(class, name, signature, slot)` 的完整清单。
- `slot=6/33/94/113/144` 分别对应 FindClass / GetMethodID / GetFieldID /
  GetStaticMethodID / GetStaticFieldID；`slot=215` 是 RegisterNatives。
  字段补法因此是逐字的：事件给什么签名就声明什么。
- `10107` 不跑：参数 `Object[0]`，返回 `Long`（真机 476930838696），Java 侧只把它
  传给 `SecurityGuardManager.nativeSetOsmssFunctionBridge`；本 runner 不执行那条
  Java 链。它的 native 路径还会触发 `exit_group`（后台线程竞态）。

## 2. 框架补齐（runtime）

平台包（`code/src/runtime/jni/envs/`）：

| 位置 | 内容 |
|---|---|
| `java_lang.cpp` | `ClassLoader.loadClass`；`Class.forName` / `getDeclaredMethods` / `getDeclaredMethod` / `getDeclaredFields`；`java.lang.reflect.Method/Field/AccessibleObject`（对象内 `__id` 指向 MethodRecord/FieldRecord）；`Method.invoke`、`Field.get/getBoolean/getInt/getLong`；原始类型 `TYPE`（`int.class` 等） |
| `java_util.cpp` | `Map.values` → `Collection`/`Iterator`（活视图）；`Enumeration`；`ArrayList` |
| `java_net.cpp`（新） | `NetworkInterface`/`InetAddress`：接口枚举为空，成员齐全 |
| `java_io.cpp` | `FileDescriptor` + `descriptor` 字段 |
| `java_world.*` | `declaredMethods()` / `declaredFields()` 枚举 API |

JNI 层（`jni_state.cpp`）：

- 浮点**返回值**按 ABI 直接使用 s0/d0（v0 低位）返回；浮点字段读写也放开。
  浮点**参数**仍在 s0-s7，尚未读取（目前到达的浮点方法都是无参 getter）。
- `DUCKEMU_JNI_TRACE` 诊断开关。
- `exit_group` 日志带 guest PC 与 tid（`thread_handlers.cpp`），用于区分
  “正常退出”和“自检失败”。
