## 3. 打包重定位

### 3.1 `DT_ANDROID_RELA`（APS2）

按 ROM `bionic/linker/linker_reloc_iterators.h::for_all_packed_relocs` 实现，**不是**
三元组：

```text
magic "APS2"                        (4 字节，DT_ANDROID_RELASZ 含 magic)
num_relocs = sleb128
r_offset   = sleb128                (初值)
while emitted < num_relocs:
    group_size  = sleb128
    group_flags = sleb128
    offset_delta = flags & 2 ? sleb128 : 0
    if flags & 1: r_info = sleb128   (组内共享)
    addend_mode = flags & (8|4)
    if addend_mode == 8: 每个 reloc 一个 addend delta
    elif addend_mode == 12: 组内一个 addend delta
    else: r_addend = 0
    for i in group_size:
        r_offset += flags&2 ? offset_delta : sleb128
        if !(flags&1): r_info = sleb128
        if addend_mode == 8: r_addend += sleb128
        emit {r_offset, type=r_info&0xffffffff, sym=r_info>>32, r_addend}
```

- SLEB128 按 64 位有符号解码；`r_addend` 是累加量
- `DT_ANDROID_REL`（0x6000000F）是 32 位 Rel 版本，arm64 不产；遇到报明确错误
- 解析结果并入 `relocations_`，与普通 RELA 同一应用路径

### 3.2 `DT_RELR`

按 ROM `bionic/linker/linker.cpp::soinfo::relocate_relr()`：

```text
base = 0
for entry in relr_table:
    if entry 为偶数:
        reloc(entry); base = entry + 8
    else:
        offset = base
        e = entry
        while e != 0:
            e >>= 1
            if e & 1: reloc(offset)
            offset += 8
        base += 63 * 8
```

`reloc(addr)` = guest 内存里的 `[addr] += module.base`。解析阶段把它展开成
`RELATIVE { offset, addend = 文件里的原值 }`；如果目标落在 `p_filesz` 之外（`.bss`），
addend 取 0。这样 applier 不需要新类型。

## 4. TLS

### 4.1 布局

沿用 M1 的 arm64 TCB 布局，在主线程 TLS 区尾部追加模块静态 TLS 区：

| 偏移 | 内容 |
|---|---|
| `0x000` | TCB（slot -2 起） |
| `0x010` | TP |
| `0x100` | DTV |
| `0x200` | bionic_tls |
| `0x3200` | pthread_internal_t 桩（M1 用） |
| `0x4000` | 模块静态 TLS 段起点 |

区域大小从 `0x4000` 扩到 `0x10000`；`kTpBase = 0x10`。
`TlsLayout::Reserve(size, align)` 返回 **TP 相对偏移**（`block_offset - kTpBase`），
对齐上限一页（与 bionic 一致）。

### 4.2 简化：所有 PT_TLS 模块都按静态 TLS 分配

bionic 只给 `DF_STATIC_TLS` 的模块静态槽，其余走 DTV 动态 TLS。M4.5 不执行，
没有 `dlopen` 之后的 TLS 访问，因此**统一按静态分配**：

- 每个 `PT_TLS` 模块拿到 `tls_offset`（TP 相对）和 1 起的 `tls_module_id`
- `TPREL64` = `tls_offset + st_value + addend`
- `DTPMOD64` = `tls_module_id`；`DTPOFF64` = `st_value + addend - TLS_DTV_OFFSET`（arm64 为 0）
- `TLSDESC` 描述符 = `{func = 静态 resolver 桩, arg = tls_offset + st_value + addend}`
- 弱未定义 TLS 符号：描述符 `{weak 桩, arg = addend}`，TPREL/DTPMOD 写 0

M4.6 必须把这套偏移通过 `__loader_shared_globals()->static_tls_layout` 交给真 libc，
否则 `pthread_create` 分配的 TLS 与重定位值对不上。这是 M4.5 与 M4.6 的硬接口。

### 4.3 TLSDESC resolver 桩

首次需要时用 `RuntimeMemory::map(0x1000, R|X, "loader-tlsdesc")` 分配一页：

```asm
static:  ldr x0, [x0, #8] ; ret          ; 返回 arg，调用方再加 TP
weak:    str x19,[sp,#-16]!
         ldr x19,[x0,#8]
         mrs x0, tpidr_el0
         sub x0, x19, x0
         ldr x19,[sp],#16
         ret
```

描述符布局 `{func, arg}`（AArch64，见 ROM `linker/linker_tls.h`）。

### 4.4 模板物化

`loadLibrary` 之前主线程 TLS 已经创建。loader 分配完槽位后，通过回调让
`TlsManager` 把 `PT_TLS` 的 `filesz` 字节写到 `block_base + tls_offset + kTpBase`，
`memsz` 其余部分保持零。M4.5 只需要主线程；子线程（M3 裸 blob 的 clone 自带 TP）
不在本轮范围。

## 5. IFUNC

### 5.1 ABI

ROM `bionic/libc/bionic/bionic_call_ifunc_resolver.cpp`：

```text
resolver(hwcap | (1<<62), &__ifunc_arg_t{size=24, hwcap=0, hwcap2=0})
```

本实现 `hwcap = 0`，libc 的 `memcpy_resolver` 会走通用实现。条目地址按 resolver 缓存。

### 5.2 延迟解析（关键）

`loadLibrary` 持有执行锁；而 `scheduler->callFunction` 是请求主 guest 线程执行，
主线程需要同一把锁 → 在锁内直接调 resolver 会死锁。

因此：

1. `RelocApplier` 遇到 IFUNC 符号或 `R_AARCH64_IRELATIVE`（1032）时，把
   `{place, resolver}` 放进 `ModuleLoader` 的 pending 列表，先写 0
2. `RuntimeInstance::loadLibrary` 释放执行锁后，逐个
   `scheduler->callFunction(resolver, {hwcap, arg_ptr})`
3. 回到锁内把结果写回 `place`
4. 再做 init_array（M4.6 之前没有 init_array 可跑）

失败时与 load 失败同样处理：丢弃 pending，实例进入 Faulted。

`ModuleLoader::lookup` 对 IFUNC 导出仍返回 resolver 地址（M4.5 不解析宿主侧 IFUNC 调用）。

### 6.1 虚拟模块只剩 linker 提供的部分

## 8. gate 断言（`04b_libc_map`）

1. **libc**
   - `Load libc.so` 的 detail 是文件路径，不是 `virtual`
   - `Needed`：`ld-android.so -> virtual`、`libdl.so -> 文件`
   - `TPREL64`（`base+0xcebe0`）== libc 模块的 `tls_offset`（符号值为 0、addend 0）
2. **libm**
   - APS2 的 1 条 GLOB_DAT：`signgam` GOT 指向 libc 的 `signgam`
   - RELR 的 27 条：抽查 `base+0x37000` 等槽位 == `base + 链接期值`
3. **libdl**：12 条 JUMP_SLOT 全部落到虚拟 `ld-android.so`，无未解析
4. **libz**：APS2/RELR + IFUNC 导入；`memcpy`/`memmove` 的 GOT 指向 libc 的
   `__memmove_aarch64`（hwcap=0 走 eq 分支，`base_c + 0x54d00`）
5. **libsgmainso 完整闭包**
   - `Load`：`libmain.so`（soname）、`liblog.so`、`libc++.so`、`libz.so`
   - `Needed` 边全部 ok；`liblog -> libc++` 可见
   - 导出的 `crc32`/`inflate`/`deflate` 等符号能查到；无未解析
6. **ModuleEvent** 中不存在 `ok=false` 的 Needed/Resolve

## 9. 不做 / 已知限制

- 不跑 `DT_INIT` / `init_array` / `preinit`（M4.6）
- 不实现符号版本（`DT_VERSYM`/`DT_VERNEED`）；这批库按名字无歧义
- 不实现动态 TLS 的 DTV 扩容：所有 PT_TLS 按静态槽处理（§4.2）
- `__loader_*` 全是返回 0 的桩；`__loader_shared_globals` 的字段留给 M4.6
- 不实现 `dlopen`/`dlclose` 运行期语义
- IFUNC resolver 只在本机执行；带 `/proc` 或 syscall 依赖的 resolver 不保证
- `libsgmainso` 的导入大部分要等 M4.6 的 syscall 面才可执行，本轮只验证绑定
- ROM 依赖与 DuckEmu libc 版本混搭只在加载层验证；M4.6 收敛到单一 ROM
