## 1. Gate 输出

### 01_tls_read

Guest（`tests/fixtures/blobs/01_tls_read.S`）：

```asm
mrs x5, tpidr_el0        // TP
ldr x6, [x5]             // slot 0  = DTV
ldr x6, [x5, #8]         // slot 1  = pthread_internal_t*
ldr w7, [x6, #768]       // errno_value
ldr x6, [x5, #40]        // slot 5  = stack guard
ldur x6, [x5, #-8]       // slot -1 = bionic_tls*
```

实测（`build/tests/01_tls_read`）：

```
tp=0x40010010 dtv=0x40010100 thread=0x40013200 errno=0
guard=0xfd7a8b4c1838ca77 bionic_tls=0x40010200
01_tls_read: OK
```

断言：

- TP 非空、16 字节对齐；DTV 非空；pthread_internal_t* 非空；bionic_tls* 非空。
- `errno_value == 0`；`stack_guard != 0`。
- `DTV[0]`（generation）= 0。
- `[thread + 760]`（pthread_internal_t::bionic_tls）== `[TP - 8]`（slot -1）。
- `[thread + 768]`（errno_value）== guest 读到的值。

**与里程碑原文的差异**：原文写的是“`mrs x0, tpidr_el0; ldr x0, [x0]` 读到
tcb->self”。arm64 没有 self 槽，`[TP]` 是 DTV。修正依据见
`2026-10-28-04-M1-TLS布局与门禁修正.md`。

### 02_pure_native

Guest（`tests/fixtures/blobs/02_pure_native.S`）依次执行：

1. `getpid()`、`gettid()`
2. `mmap(NULL, 4096, RW, MAP_PRIVATE|MAP_ANONYMOUS, -1, 0)`
3. 在新映射里写/读 `0x1234`
4. `mprotect(addr, 4096, PROT_READ)`
5. 通过 thunk 页调用 host stub `host_add(pid, tid)`
6. `write(1, "m1\n", 3)`
7. `munmap(addr, 4096)`
8. 返回 `loaded + host + write + munmap + mprotect`
9. 第二个 blob 调 `exit_group(7)`

实测（`build/tests/02_pure_native`）：

```
m1
pid=1000 tid=1 mmap=0x40018000 loaded=0x1234 mprotect=0
host=1001 write=3 munmap=0
02_pure_native: OK
```

- `m1` 是 guest 通过 `write` 真正写到了宿主 stdout（返回 3）。
- 返回值 = `0x1234 + 1001 + 3 + 0 + 0 = 0x1620`（5664），断言通过。
- `exit_group(7)` 让 `callFunction` 返回 `exit_code = 7`，而不是返回陷阱。
- 全程没有 JNI、没有 ELF loader、没有多线程。

## 3. 关键实现决定

1. **Unicorn 页大小**：`uc_open` 之后、第一次 map/run 之前调用
   `uc_ctl_set_page_size(0x1000)`。M0 实测默认是 `0x400`（1 KiB），与 Android
   4 KiB 页不一致。
2. **内存唯一权威**：`RuntimeMemory` 持有 host mmap 后备；backend 只负责把每个
   region 用 `uc_mem_map_ptr` 镜像到 engine。map/unmap/protect 通过
   `MapObserver` 通知 backend。
3. **SMC**：宿主写可执行 region 走 `CodeWriteNotifier`；guest 写可执行页由
   `UC_HOOK_MEM_WRITE` 查 region perms 后 `uc_ctl_remove_cache`。
4. **SVC 解码**：`UC_HOOK_INTR` 里 PC 已经是 `svc+4`；从 guest 内存读 `PC-4`
   的指令，校验 SVC 编码后取 imm16。`imm == 0` 是 Linux syscall（号在 x8），
   `imm & 0x8000` 是 host stub（index = imm & 0x7fff）。
5. **thunk**：一页 RX（`0x70000000`），每项 8 字节：
   `svc #(0x8000|index); ret`。参数不搬运（AAPCS64 已在 x0..x7），host stub
   返回值写 x0，`ret` 回到 guest 的 LR。
6. **调用约定**：`callFunction` 把 SP 设为实例栈顶、LR 设为 return trap、写
   TPIDR_EL0 与 x0..x7，然后 `uc_emu_start(entry, return_trap)`。guest 返回或
   `exit_group` 都从 `uc_emu_start` 退出；后者由 dispatcher 的 exit 状态表达。
7. **TLS**：TCB 10 个槽（TP-16..TP+56），slot 0 = DTV、slot 1 =
   pthread_internal_t*、slot 5 = stack guard、slot -1 = bionic_tls。errno 在
   pthread_internal_t + 768，不在 slot 2。
8. **错误返回**：handler 直接返回 `-errno`；dispatcher 写 x0，PC 不动（M0
   Probe 3 验证过）。未实现 syscall 返回 `-ENOSYS` 并打日志。

## 4. M1 明确没做（留给后续）

- ELF loader、JNI、多线程、VFS、APK、Dynarmic（按里程碑）。
- 文件 mmap → 目前 `-ENODEV`（M4）。
- 阻塞 syscall（futex/nanosleep）→ M3。
- 未实现 syscall 的 guest 调用栈 dump → M2。
- 16KB 页 Android 目标的页大小配置（北极星确定后）。
- 全局/局部引用、`__errno()` 的语义完整化（M4/M5 真实 .so 读到时再补
  pthread_internal_t 的其余字段）。
- `read` 只支持 fd 0；`write` 只支持 fd 1/2；单次 1 MiB 上限（M1 够用，VFS 后替换）。
