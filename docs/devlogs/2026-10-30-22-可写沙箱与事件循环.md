## 1. VFS 写：per-instance 可写沙箱

模型是**覆盖层**：一个宿主目录代表 guest `/` 的写侧，读/stat 先查它，
未命中再落到只读根。因此 `open(O_CREAT)` 建的文件对之后所有读都可见，
而只读根保持不动（不会被写穿）。

| 面 | 行为 |
|---|---|
| `openat` | 接受 `O_WRONLY/O_RDWR/O_CREAT/O_TRUNC/O_APPEND/O_EXCL`；没有沙箱时仍 EROFS |
| 路径安全 | 只 canonicalise 父目录（叶子可能还不存在），拒绝逃出沙箱根的 symlink |
| `mkdirat` | 在沙箱里真正建目录（此前固定 EROFS） |
| `unlinkat` / `renameat` | 只在沙箱内；只读根上的路径回 EROFS |
| `ftruncate` / `fsync` / `fdatasync` | 走 `File::truncate/sync` |
| `stat` 元数据 | uid/gid 来自配置；注入时钟模式下 atime/mtime/ctime 用注入值，回放字节一致 |
| `faccessat(W_OK)` | 只对沙箱内的文件成立，宿主只读根本身的可写权限不外泄 |

配置：`RuntimeConfig.filesystem_write_root / file_uid / file_gid`，
经 worker `--filesystem-write-root`、system 规格
`,filesystem-write-root=DIR` 贯通。

## 2. 事件循环

### 2.1 调度器先长出"带截止时间的阻塞"

原来的阻塞只有 futex，且超时直接 `ENOSYS`。现在：

- `RuntimeThread` 增加 `deadline / deadline_expired`；
- `ThreadSystem::parkThread(thread, pending, timeout_us)` 挂起任意
  `PendingSyscall` 并可选截止时间；
- 截止在阻塞线程自己的 host loop 里只置 `deadline_expired`，等它重新
  拿到执行锁后由 `expireDeadline()` 调 `complete(TimerExpired)` ——
  完成回调写 guest 内存，必须在锁内；
- futex 的 `struct timespec` 超时复用同一机制（到期从等待队列摘除）。

### 2.2 对象与 syscall

| 面 | 实现 |
|---|---|
| `eventfd2` | 64 位计数器，`EFD_SEMAPHORE`；空时读 EAGAIN、满时写 EAGAIN |
| `timerfd_create/settime/gettime` | 宿主 steady 时钟，单次/周期；read 收走到期次数 |
| `pipe2` | 共享 64 KiB 缓冲的一对端，写端 POLLOUT、读端有数据才 POLLIN |
| `poll/ppoll` | 逐 `pollfd` 求值；无就绪则挂起 |
| `pselect6` | 三组 fd_set，返回就绪个数并把就绪集合写回 |
| `epoll_create1/ctl/pwait` | 注册表在 `EpollFile`，就绪在 handler 侧按 fd 表求值；`epoll_event` 是 packed 12 字节（events@0, data@4） |

### 2.3 唤醒来源

- **deadline**：调用方超时；
- **timerfd 压缩截止**：等待集合里有 timerfd 时，park 的截止时间取
  `min(用户超时, 最近一次 timer 到期)`。否则 timerfd 就绪没有任何东西
  能唤醒等待者（一个自食其果的坑，第一版测试就踩到了）；
- **activity 唤醒**：任何经 guest 的读/写成功后
  `VirtualFileSystem::notifyActivity()`，所有阻塞等待者被唤醒并重新
  求值；仍然不满足就返回 `nullopt`（spurious），继续睡。

限制：管道/eventfd 的**阻塞读**本身仍返回 EAGAIN（等待只经 poll/epoll），
这与"先 poll 再读"的目标写法一致；没有建模 `signalfd`、`ioctl`。
