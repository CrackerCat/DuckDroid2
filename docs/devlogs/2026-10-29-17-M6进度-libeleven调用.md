## 1. 项目落地

`code/user_code/libeleven_case/` 现在是完整的目标项目：

```text
libeleven_case/
├── libeleven_env.hpp    # installEnvironment 声明（唯一对外入口）
├── libeleven_env.cpp    # 目标类 + data(I)Ljava/lang/String; 声明
├── main.cpp             # 显式安装环境 → 加载 ROM libc + assets/libeleven.so → 调 data(n)
└── assets/libeleven.so  # 目标 so（与 DuckDroid 的副本逐字节相同）
```

构建与运行：

```bash
cmake --build build --target duckemu_libeleven_case
./build/user_code/duckemu_libeleven_case 1 5
```

接线方式是**显式安装**（2026-10-29 用户质疑“main.cpp 里看不到调用”后改的）：
`main.cpp` 在 `create` 之后、任何 `loadLibrary` 之前调用
`instance.installJavaEnvironment(&user::libeleven::installEnvironment)`。
不写静态注册器、不写名字注册表、不改 `RuntimeConfig`；晚于模块加载会被 runtime 拒绝。

`main.cpp` 注册 `JniEvent` 监听：任何项目没声明的类/方法/未实现槽都会打到 stderr，
不会静默返回默认值。

**这个文件是必需的**（实测）：把安装调用临时去掉后，`JNI_OnLoad` 的
`FindClass` 报 `missing-class ChallengeElevenFragment`，`RegisterNatives`
拿到 null class 也报 `missing-class`，随后 `callRegisteredNative` 直接失败。
没有任何静默兜底。

## 2. 实测结果

`data(1..5)`：

```text
data(1) = cT0uYLyLcJVRYLyjYJEi
data(2) = cJ0uYLyLcJVRYLyjYJIW
data(3) = cL0uYLyLcJVRYLyjYJIW
data(4) = Yo0uYLyLcJVRYLyjYJIW
data(5) = YT0uYLyLcJVRYLyjYJIu
```

用 so 里的自定义码表（文件偏移 `0xa1c29`，
`45AogfZw/9+FcYrSVH1TKM7k3BebEtqCIGPJyQD60lUXpNmhWuRLds8jainzv2Ox`）反解：

```text
data(1) -> 1:1793242797679
data(2) -> 2:1793242797680
data(3) -> 3:1793242797680
data(4) -> 4:1793242797680
data(5) -> 5:1793242797681
```

与 DuckDroid `libeleven_case/README.md` 记录的结构一致：
`custom_b64(f"{n}:{now_ms}")`。`1..100` 全量运行退出码 0，约 1.5 s，
stderr 没有任何 `JniEvent`（无缺失类/方法、无未实现 JNI 槽）。

这一轮同时验证了：ROM libc preinit、libc++ 的 `system_clock`、`clock_gettime`
syscall、JNI `NewStringUTF`、`callRegisteredNative` 返回值、`jniStringUtf8`
整条链路。
