# /dev 字符节点：null / zero / random / urandom

> 日期：2026-10-30
> 缺口审计 A 组第 4 项。属性区（`2026-10-30-24-属性区.md`）留下的只读合成挂载
> 接口直接派上用场。

## 1. 做了什么

`/dev` 现在是第二个 `SyntheticFileSystem`（第一个是 `/dev/__properties__`）：

| 节点 | 读 | 写 | st_rdev |
|---|---|---|---|
| `/dev/null` | EOF（0 字节） | 接受、丢弃 | 1:3 = `0x103` |
| `/dev/zero` | 全 0，长度 = 请求 | 接受、丢弃 | 1:5 = `0x105` |
| `/dev/random` | 实例随机流 | 接受、丢弃 | 1:8 = `0x108` |
| `/dev/urandom` | 实例随机流 | 接受、丢弃 | 1:9 = `0x109` |

`/dev` 本身也作为目录节点可 `stat`（`getdents64` 仍未做，见审计第 2 项，
所以 `opendir("/dev")` 还是不行）。

## 2. 接口上的三处扩展

1. **`SyntheticNode` 支持流式节点**
   新增 `create(path, flags)` 工厂：块内容（`content`）仍是不可变字节数组，
   字符设备则由工厂按打开标志构造 `DeviceFile`。打开模式随描述走：
   `O_WRONLY` 的 `read` 返回 EBADF，`O_RDONLY` 的 `write` 在 `sysWrite`
   的 `writable()` 检查处返回 EBADF（与内核一致，测试覆盖）。
2. **VFS 支持多个合成挂载**
   `VfsConfig::synthetic` 变成 `synthetic_mounts`（后者覆盖前者）。
   `/dev` 与 `/dev/__properties__` 互不重叠，顺序只影响未来叠挂。
   `access(2)` 不再对合成节点一律拒绝写，而是按节点 mode 的权限位判断
   （设备 0666、属性 0444、目录 0555）。
3. **`FileStat::rdev`**
   arm64 `struct stat` 的 `st_rdev` 在偏移 32，之前一直写 0。现在随
   `writeStat` 写出；字符设备的 `S_ISCHR` 与 `major/minor` 终于是真的。

## 3. 随机源：一个实例一条流

`getrandom(2)` 原来用 `thread_local mt19937_64`（每线程一份宿主种子）。
现在换成 `RandomSource`（`runtime/random/random_source.*`）：

- 一个 `RuntimeInstance` 一条流，`getrandom(2)` 与 `/dev/{u,}random`
  共用，两个观测面不会各说各话；
- 互斥量保护，guest 线程可以并发读；
- 构造函数已经支持 `RandomSource(uint64_t seed)`，审计第 5 项
  （RNG 可注入）只剩"配置里给种子"这一步，行为不变。

`AT_RANDOM`（`shared_globals.cpp`）仍是宿主 `random_device`，属于第 5/11 项。

## 4. 测试

`04j_dev_nodes`，全部经 ROM libc 的 `open/read/write/fstat/stat/access/lseek`：

- `/dev/null`：读 EOF、写回长度、`O_RDWR` 下 lseek、fstat 是 `S_IFCHR`、
  rdev `0x103`、uid/gid 0；
- `/dev/zero`：先投毒再读 64 字节，全 0；`O_RDONLY` 写返回 -1，
  `O_RDWR` 写回长度；rdev `0x105`；
- `/dev/urandom`：两次 64 字节非全零且互不相同；rdev `0x109`；
- `/dev/random`：读 32 字节；
- `getrandom(2)` 仍返回全部字节；
- `stat("/dev")` 是目录；`access("/dev/null", R_OK/W_OK)` 通过、
  `X_OK` 失败。
