# JD 16.1.50 接入：JNI 面补全与精简 APK

> 日期：2026-10-29
> 目标：把 `DuckDroid/code/user_code/jdgs_16` 的京东签名案例移植到
> `code/user_code/jdgs_case/`，按 `ENVIRONMENT.md` 的组织方式，只带目标真正
> 需要的资产与声明。

## 1. 参考实现给出的 JNI 面

直接跑 DuckDroid 的参考 runner（`JDGS_TRACE_JNI=1`）得到完整调用面：

```text
FindClass / GetMethodID / GetStaticMethodID / GetFieldID / GetStaticFieldID
NewStringUTF / GetStringUTFChars / ReleaseStringUTFChars
NewByteArray / SetByteArrayRegion / NewObjectArray
GetArrayLength / GetObjectArrayElement
NewObjectV / CallObjectMethodV / CallStaticObjectMethodV
GetObjectClass / GetObjectField / IsInstanceOf / ExceptionCheck / DeleteLocalRef
```

DuckDroid2 的 M5 当时明确把数组和 `*V` 变参列为未实现，因此这次不是纯搬
代码，而是先补 runtime 面再写目标环境。

## 2. runtime 补了什么

| 面 | 位置 | 说明 |
|---|---|---|
| 数组对象 | `JavaWorld` | `ArrayElementKind`/`ArrayView`，数组类按需声明（`[B`、`[Ljava/lang/Object;`），元素存储在 JNI arena |
| 数组 JNI | `JniState::accessArray` | `GetArrayLength`、`New*Array`、`NewObjectArray`、`Get/SetObjectArrayElement`、`Get/Release*ArrayElements`、`Get/Set*ArrayRegion` |
| 变参 | `abi_adapter` | AAPCS64 `va_list{stack,gr_top,vr_top,gr_offs,vr_offs}` 顺序读取并回写游标 |
| 构造 | `JniState::newObject` | `NewObject(V/A)`：分配对象后调用 host shim 或嵌套 native 构造器 |
| 字段描述符 | `JavaWorld::declareField` | 接受 `Ljava/lang/String;`、`[L...;`，不再只接受单字符 |
| `void` 返回 | `jni_types` | 之前 `parseMethodSignature` 把 `)V` 当非法；构造器/void 方法全部受影响 |
| host 结果 | `RuntimeInstance::jniResolveHandle` | runner 把对象结果句柄换成对象地址，再由项目环境读取 |
| 对象参数 | `callRegisteredNative` | `L...;` / `[...` 位置的实参按对象地址处理，自动包本地引用；每次调用一个本地帧 |
| 平台 String | `envs/java_lang.cpp` | `String([B,String)` 与 `getBytes(String)`，固定 UTF-8 |
| 导入桩 | `virtual_modules` + `symbol_lookup` | `libandroid.so`/`libmediandk.so` 的符号按 requester 的 `DT_NEEDED` 解析为返回 0 的 thunk；不污染全局严格性 |
| 文件根 | `RuntimeConfig.filesystem_roots` → Worker `--filesystem-root` | 目标通过 guest 路径读自己的 APK |
| syscall | `memory_handlers` / `fs_handlers` | `madvise`（`MADV_DONTNEED` 清零）与 `mkdirat`（EROFS） |

两个隐藏问题是真实目标才暴露的：`void` 返回签名此前从未被平台包使用；
`declareField` 的对象描述符同理。

## 3. 精简 APK

完整 APK 82 MiB。做消融实验：只保留 native 读到的 9 个条目，构造一个
106 KiB 的 ZIP，替换参考 runner 的 APK 后仍能签出相同的 `b1/b2/b3/b5`，
说明其余内容不参与签名路径：

```text
assets/<appkey>.jdg.{jpg,xbt}
assets/jdjdg-appkey.txt
assets/jdmp/jdg-evn-scnr.{bdex,edex,jdex,json}
assets/rootcert/secure_root.cer
META-INF/JINGDONG.RSA
```

APK 经 `filesystem_roots` 挂在
`/data/app/com.jingdong.app.mall-NMPcDqBzdYwQrAm-23cOyQ==/base.apk`。

## 4. 验证

- `Bridge.main(103, ["0"])`、`(["1", null])` 后 `main(101)` 输出 7 字段 JSON；
  `b1/b2/b3/b5` 与参考一致。
- 注入 `JDGS_WALL_TIME_MS=1792886400000` 后，**整个输出与 DuckDroid 参考
  runner 逐字节相同**（含 `b4/b6/b7`）。
- `jdgs_env.cpp` 保存 `JavaWorld*` 以便 runner 构造 `Object[]`；一个进程一个
  实例的约束与 worker 的实例进程模型一致。
- gate：`05_jni_arrays`（数组 + `NewObjectV` + `CallStaticObjectMethodV`）、
  `07e_jdgs_plugin`（`make_app_plugin` → init → 两次 invoke）。
  默认与 `-Werror` 全量 34/34；两者在 ASan 下单独复核通过。

## 5. 已知限制

- `String` 的 charset 固定按 UTF-8 解释；当前样本只用 UTF-8。
- 没有可写 guest home：`getFilesDir` 返回一个声明出来的 `File`，路径已
  绝对化；native 尝试 `mkdirat` 得到 `EROFS` 后继续。
- worker 实例的 guest 调用超时仍是默认 5 s；JD 初始化实测约 1–2 s，若后续
  目标超过，需要在 worker 配置里加 timeout 透传。
- `madvise` 的 `MADV_FREE` 视为 no-op（内核允许延迟回收）；`MADV_DONTNEED`
  按内核语义清零。
