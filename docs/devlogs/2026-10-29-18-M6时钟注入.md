# 2026-10-29 M6 时钟注入（DuckDroid 对齐）

> 前置：`2026-10-29-17-M6进度-libeleven调用.md`
> 依据：DuckDroid `code/engine/os/os_state.cpp` 的 `NextClock` /
> `SetWallTimeNs` / `SetMonotonicTimeNs`。

## 1. 抄了什么

DuckDroid 的时钟语义：

- 默认：直接读宿主 `system_clock` / `steady_clock`；
- 注入后（`SetWallTimeNs` / `SetMonotonicTimeNs`）：**返回当前值，然后 +1 ms**；
- `clock_gettime` 只看 `clock_id == 0` 区分 realtime/monotonic；
- `nanosleep` / `clock_nanosleep` 把请求时长加到时钟上（不真睡）。

DuckDroid2 落成 `src/runtime/clock/runtime_clock.{hpp,cpp}`，语义一致：

```cpp
uint64_t nextRealtimeNs();   // 注入时返回当前值并 +1 ms；否则宿主时间
uint64_t nextMonotonicNs();
void setWallTimeNs(uint64_t ns);
void setMonotonicTimeNs(uint64_t ns);
void useHostWallClock();
void useHostMonotonicClock();
```

对外 API 在 `RuntimeInstance`：`setWallTimeNs` / `setMonotonicTimeNs` /
`useHostWallClock` / `useHostMonotonicClock`（命名按本仓库 camelCase，
语义与 DuckDroid 的 `SetWallTimeNs` 一致；`0` 是合法注入基准，不是“恢复宿主”）。

## 2. 接线

所有取时间的路径共用同一个实例级 `RuntimeClock`：

| 路径 | 之前 | 现在 |
|---|---|---|
| `clock_gettime(CLOCK_REALTIME)` | 宿主 `system_clock` | `ctx.clock.nextRealtimeNs()` |
| `clock_gettime(CLOCK_MONOTONIC/_RAW/_COARSE/BOOTTIME)` | 宿主 `steady_clock` | `nextMonotonicNs()` |
| `clock_gettime(REALTIME_COARSE)` | `EINVAL`（缺失） | realtime |
| `clock_gettime(PROCESS/THREAD_CPUTIME)` | 写 0 并成功（伪造） | monotonic（DuckDroid 同款近似） |
| `gettimeofday` | 宿主 `system_clock` | `nextRealtimeNs()` |
| `java.lang.System.currentTimeMillis/nanoTime` | 各自读宿主 | 同一个时钟 |

接线位置：`RuntimeInstance::Impl` 持有 `RuntimeClock`，`JavaWorld` 与
`SyscallContext` 各拿一个引用；所有 guest 线程共享。非法 clock id（如 99）
仍返回 `EINVAL`，没有照抄 DuckDroid 的“非 0 即 monotonic”。

## 3. 证据

`06_clock_injection` 注入 `1792886400000000000` ns（2026-10-01T00:00:00Z），
调用真实的 libeleven：

```text
first = 1:1792886400000
second = 1:1792886400001
third  = 100:1792886400002
```

`data(n)` 每次只读一次 `CLOCK_REALTIME`（M5 的 trace 已确认），所以每调用一次
时间前进 1 ms；同一输入序列在任何进程里逐字节一致。恢复宿主时钟后
`data(1)` 又回到真实墙钟。

runner 也支持同样参数：

```bash
./build/user_code/duckemu_libeleven_case \
  --wall-time-ns 1792886400000000000 1 3
# 反解：1:1792886400000 / 2:1792886400001 / 3:1792886400002
```

测试：

- `runtime_clock_test`：宿主/注入、1 ms 步进、0 基准、恢复宿主、饱和；
- `jni_world_test`：`System.currentTimeMillis` / `nanoTime` 走同一注入时钟；
- `06_clock_injection`：libeleven `data()` 的确定性序列 + 恢复宿主；
- `04c_syscalls`：COARSE 时钟不再 EINVAL，CPU 时间时钟不再返回 0。

## 4. 还没做

- `nanosleep` / `clock_nanosleep` 尚未实现；等落地时按 DuckDroid 的
  `AdvanceSleep` 把时长加到注入时钟上（不是真实睡眠）。
- CPU 时间时钟目前用 monotonic 近似；真正需要 CPU 时间的目标再实现。
- 时区/`localtime` 未处理；libeleven 只用 epoch 毫秒。
