# 2026-10-28 M2 设计：可观测性

> 本文是 M2 的实现前设计。gate 与交付物见 `docs/里程碑.md` M2 一节；
> trace 家族格式的既有权威是 `/home/duck/NewCode/Android/Trace/docs/TraceFormat.md`
> （QBDI + Frida 的指令级四件套），本文不复制它的语义，只继承它的约定。
>
> 读完的两份既有材料：
> - `TraceFormat.md`：三文件（code.log / bl.log / rw.log）+ `mem/`，行号 = 第 N 条指令，
>   tab 分隔、数值 `0x` 小写十六进制、寄存器与 note 列是 JSON、`insn` 列带引号。
> - `Trace/code/QDBI/trace`：`syscall_names.inc` 是可复用的 syscall 名表。

## 1. 范围

M2 只做观测，不改任何 Android 语义。产出三样：

1. **语义通道**：`SvcEvent` + `MemoryEvent`，同步、可靠、按 guest 顺序。
2. **诊断通道**：SPSC 环形缓冲 + 丢失计数，高频、可丢、默认关闭。
3. **两份可见物**：`svc.log`（可解析、可 diff 的文本）与未实现调用的 guest 栈 dump。

gate：

- `02_pure_native` 输出完整 svc trace（并断言 8 条记录的内容）
- `02_stack_dump`：未实现 syscall → dump 出完整 LR 帧链（逐帧断言）

## 2. 与既有 trace 家族的关系

**共享约定，不共享索引体系。**

| 项 | QBDI 四件套 | DuckEmu svc.log |
|---|---|---|
| 载体 | 纯文本、tab 分隔 | 同 |
| 数值 | `0x` 前缀小写十六进制 | 同 |
| 列表列 | JSON | 同 |
| 首列 | `line` = 第 N 条**指令**（连续无空洞） | `seq` = 第 N 次**SVC 分发**（连续无空洞） |
| 文件 | code/bl/rw + mem/ | 只有 svc.log |
| 无注解 | `{}` | 同 |

不能复用 `code.log` 的原因：DuckEmu 不做指令级 trace（Unicorn 的 `count` 预算
等价于每指令 hook，见架构评审 §2），没有指令序号，也就不存在
`line → bl/rw` 的关联。硬塞进 code.log 会破坏「首列 == 指令序号」这条解析器地基。
指令级四件套留给 M6 的分析模式，到那时 DuckEmu 自己产出同构文件，两边靠
**地址**对齐，不靠行号。

`syscall_names.inc` 直接从 `Trace/code/QDBI/trace` 复制（NDK 生成，与 asm-generic
号码一致，已抽查 `write`/`exit_group`/`getpid`/`mmap`/`mprotect`/`munmap`/`clone`），
放到 `src/runtime/svc/syscall_names.inc`，并在文件头注明来源。

## 3. 事件模型

两条通道**物理分离**（冻结项）：

```
            同步、可靠                             异步、可丢
   SvcDispatcher ─┐                        UC_HOOK_MEM_READ/WRITE
   RuntimeMemory ─┼→ EventBus.publish ─→  listeners（trace 文件、测试）
                  │                        └→ RingBuffer<DiagnosticEvent> ─→ 宿主 drain
```

- **EventBus 归 RuntimeInstance**，`SvcDispatcher` 与 `RuntimeMemory` 持非拥有引用。
- listener 在 emu 线程内同步调用，**禁止回调 emulator**（M0 探针 6：同 engine 嵌套会覆写外层寄存器）。
- listener 抛异常会被 `publish` 捕获并记 ERROR —— 异常不能穿过 Unicorn 的 C 帧。
- publish 时对 listener 列表做快照，允许 listener 在回调里增删自己。
- M2 单线程，不加锁；M3 加实例锁时再补。

### SvcEvent

`seq` 在**进入分发时**分配，事件在**完成时**发布。M2 两者同序；M3 的阻塞 syscall 会晚完成，
所以每条记录有两个序号：`id`（**发布顺序**，`svc.log` 首列，恒单调连续）与 `seq`
（**调用顺序**）。一个 syscall 永远只有一条记录（决策 02 §3.1：不重放、不重复 trace）。

字段：`id, seq, tid, svc_address(即 PC-4), kind, number, name, args[6], result(x0 写回值),
supported, stack[], stack_stop`。

- listener 在 hook 内同步执行，重入 emulator 会覆写外层寄存器（M0 探针 6）。
  保护点在引擎入口：`EventBus::delivering()` 非零时 `callFunction` 直接返回错误。
- trace 文件由 listener 与实例**共同持有**（`shared_ptr`），不依赖成员声明顺序。

`kind`：`sys`（Linux syscall）/ `host`（thunk 上的 host stub）/ `trap`（未知 SVC imm）。

### MemoryEvent

由 `RuntimeMemory` 的公开入口（`map` / `mapFixed` / `unmap` / `protect` / `brk`）在
**成功后**发出，一条公开调用一条事件；内部的 `splitAt` / `unmapRange` 不发。
`mapFixed(replace=true)` 记为 `replaced=true`。

### 不做的类型

`ModuleEvent`、`ThreadEvent`：M2 没有生产者（无 loader、单线程）。按执行规则 5，
有生产者的那一步（M4 / M3）再建文件，现在建成空壳就是占位代码。

## 4. svc.log 格式

一行一条完成的 SVC 分发，tab 分隔 9 列：

```
id	seq	tid	svc	kind	name	args	ret	note
```

| 列 | 格式 | 例 | 说明 |
|---|---|---|---|
| `id` | `%llx` | `7` | 十六进制、无 `0x`、从 0 起连续，**发布顺序**，`svc.log` 的绝对索引 |
| `seq` | `%llx` | `7` | **调用顺序**（进入分流时分配）；M2 与 `id` 相同，M3 阻塞 syscall 后才分叉 |
| `tid` | `0x%x` | `0x1` | |
| `svc` | `0x%llx` | `0x4010020c` | `svc` 指令地址（`UC_HOOK_INTR` 里的 `PC-4`） |
| `kind` | 字面量 | `sys` / `host` / `trap` | |
| `name` | 单 token，无空格 | `mmap` / `host_add` / `sys#999` / `host#3` | |
| `args` | JSON 字符串数组 | `["0x0","0x1000","0x3","0x22","0xffffffffffffffff","0x0"]` | 恒 6 个 |
| `ret` | `0x%llx` | `0xffffffffffffffda` | x0 写回值（负数按 64 位补码） |
| `note` | JSON 对象 | `{}` | 见下 |

`note` 取值：

| 值 | 含义 |
|---|---|
| `{}` | 正常完成 |
| `{"unsupported":1,"stop":"fp=0","stack":[{"pc":"0x4010020c","name":"code-native!0x20c"},...]}` | 未实现；`stack` 是 LR 帧链，`stop` 是回溯终止原因 |

`name` 解析：`syscall_names.inc` 二分查表；查不到写 `sys#<十进制号>`。

## 5. guest 栈回溯

入口：未实现 syscall、未注册 thunk index、未知 SVC imm。读 `SP` / `X29(FP)`，以
`svc_address` 作为第 0 帧，然后沿 x29 帧记录上溯（`[fp]` = 上一帧 fp，`[fp+8]` = 返回地址）。

每帧校验，任一失败即停止并记录原因（`stop`）：

| 检查 | 失败时 |
|---|---|
| `fp == 0` | 正常终止，`stop="fp=0"`，`truncated=false` |
| `fp % 16 == 0` | `stop="unaligned fp"` |
| `fp` 仍在 `SP` 所在的 region 内（`contains(fp, 16)`） | `stop="fp outside stack"` |
| 该 16 字节可读（`memory.read`） | `stop="unmapped frame"` |
| 保存的 LR 非 0 | `stop="lr=0"` |
| 帧数 < 32 | `stop="frame limit"` |

**已知限制**（写进结果文档）：这是 x29 帧链，不是 DWARF/CFI 回溯。Android release
构建默认 `-fomit-frame-pointer`，真实 .so 上链会很短甚至只有一帧 —— 这是 unidbg
同款简单 unwinder 的固有限制，M4 真遇到再讨论 CFI。测试 blob 手写帧记录，
所以 gate 能拿到完整 4 帧。

名字解析：`regionAt(pc)` 命中 → `"<region名>!0x<偏移>"`（沿用 bl.log 的 `模块!偏移`
降级约定）；未命中 → 裸 `0x<地址>`。

配套改动：`callFunction` 把 `X29` 置 0，给帧链一个终止符（现在不清，初始值是脏的）。

## 6. 诊断通道

`RingBuffer<T>`：定长、2 的幂、SPSC、`tryPush` 满了就丢并给 `dropped` 加 1。
生产者是 emu 线程（Unicorn hook），消费者是宿主（M2 在 run 结束后 drain）。

**硬约束**：M3 每线程一个 engine 后，必须改成**每线程一个环**，不能加锁 —— 生产者是每条
guest 访存都会走的热路径。`drainDiagnostics` 的接口形状已经兼容这次拆分。

`DiagnosticEvent`：`kind(mem-read|mem-write), tid, pc, address, size, value(仅写且 ≤8 字节)`。

生产者开关：`RuntimeConfig.record_memory_access`（默认 false）。开启时 backend 额外挂
`UC_HOOK_MEM_READ|UC_HOOK_MEM_WRITE`；只收 `UC_MEM_READ` / `UC_MEM_WRITE`，
不收 `*_UNMAPPED` 等失败变体。

**不做**：指令级 snapshot。它必须和 `count` 预算、watchdog 一起设计，M3 之后再说。

## 8. gate 断言

### 02_pure_native（扩展）

- 打开 `trace_path`，运行后解析文件，断言**恰好 8 条**记录、`id`/`seq` 为 0..7、名字依次为
  `getpid, gettid, mmap, mprotect, host_add, write, munmap, exit_group`；
  `ret` 与 guest 实际拿到的值一致；mmap 的 6 个参数逐项比对；无 `unsupported`。
- listener 内调用 `callFunction` 必须被拒绝（重入保护），且 `removeSvcListener` 生效。
- 订阅 `MemoryEvent`，断言 guest 的 mmap/mprotect/munmap 各有一条，地址/权限匹配。
- 打开 `record_memory_access`，drain 后断言 `dropped == 0`，且存在
  `(write, addr=mmap 返回地址, size=4, value=0x1234)` 与同地址的 read。

### 02_stack_dump（新增）

blob 三层帧记录，最内层调 `io_setup`（syscall 0，长期不会实现）：

- 断言 trace 只有 1 条记录：`kind=sys`、`name=io_setup`、`ret=-ENOSYS`、`unsupported`
- 断言帧链 4 帧：`[0]=svc 地址`、`[1]/[2]=guest 自己存进 out 的两个返回地址`、
  `[3]` 落在 `return-trap` region（host 入口）
- guest 同时把 `-ENOSYS` 写进 out，交叉验证返回值

## 9. 明确不做

- 指令级 trace（默认关，且 M2 不开实现）
- `ModuleEvent` / `ThreadEvent` 空壳
- 异步消费者线程 / trace 落盘背压（M2 的 svc 频率用不上）
- 通用 hook 反射、事件序列化协议、跨进程
- CFI/DWARF 回溯，符号表（M4）
