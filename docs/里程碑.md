## 2. 执行规则

1. **一个里程碑 = 一个可 review 的 PR。** gate 不过，不进入下一阶段。
2. **gate 是测试文件，不是口头结论。** integration 测试即里程碑。
3. **先记录，后实现。** 实现中发现设计与实际不符：先写进 `docs/devlogs/`，再改设计文档，再改代码。
4. **每个 gate 通过后更新本文件**：改状态列，重写"当前状态"里的下一步。
5. **不提前实现下一阶段的抽象。** 特别是 M4 之前不要为 JNI 预留接口，M7 之前不要建 Dynarmic 目录。
6. 文档与源码/实测冲突时，以源码和实测为准（"错了就走实际的"）。

## 3. 各里程碑详情

### M0 探针

**目标**：不写任何抽象，直接用 Unicorn C API 验证九条语义。这九条里任何一条与设计假设不符，都必须在写 M1 之前修正设计。

**交付物**

```
code/CMakeLists.txt
code/cmake/CompilerWarnings.cmake
code/cmake/Sanitizers.cmake
code/src/common/id/ids.hpp
code/src/common/error/result.hpp
code/src/common/error/error_code.hpp
code/src/common/log/logger.hpp
code/src/common/log/logger.cpp
code/tests/CMakeLists.txt
code/tools/spike/unicorn_spike.cpp
docs/devlogs/2026-10-27-03-M0探针结果.md
```

**九条探针（全部要有实测输出）**

- [ ] 1. `svc #0` → `UC_HOOK_INTR`，intno == 2
- [ ] 2. hook 里 PC 是否等于 `svc + 4`
- [ ] 3. 不碰 PC + 写 x0，guest 从下一条继续
- [ ] 4. 挂起式：hook 里 `uc_emu_stop()`，PC 保持 `svc+4`；回宿主后写 x0，再次 `uc_emu_start` 能从 `svc+4` 继续
- [ ] 5. `mrs x0, tpidr_el0` 读到 host 写入的 `UC_ARM64_REG_TPIDR_EL0`
- [ ] 6. 同一 engine 嵌套 `uc_emu_start`（host→guest 回调），记下可用层数
- [ ] 7. 两个 engine 在两条宿主线程同时执行；`uc_mem_map_ptr` 共享内存；数据互相可见
- [ ] 8. `uc_mem_map_ptr` + `uc_mem_protect`：guest mprotect 不影响宿主映射；不同 engine 权限可不同
- [ ] 9. 跨线程 `uc_emu_stop`（watchdog）；对暂停中 engine 做 map/protect/`uc_ctl` 是否安全

**明确不做**：不建 `runtime/ worker/ system/` 任何目录；不做抽象；不做性能优化。

### M1 最小闭环

**目标**：一个单线程 guest 能跑完裸 blob，能正确读 TLS，SVC 能分发到 handler。

**交付物**

```
src/common/{id,error,log}/
src/runtime/memory/          # region 表、mmap/munmap/mprotect/MAP_FIXED、CodeWriteNotifier
src/runtime/backend/unicorn/ # engine 创建、run、request_stop、invalidate_code
src/runtime/threads/tls/     # API33 TCB 布局、TLS 实例分配
src/runtime/svc/             # dispatcher + memory/fs/misc handlers
src/runtime/memory/thunk     # thunk 页分配与 index 表
```

**Gate**

- `tests/integration/01_tls_read.cpp`：arm64 无 `TLS_SLOT_SELF`，验证
  `mrs x0, tpidr_el0`、`[TP]`=DTV、`[TP+8]`=pthread_internal_t*、
  `[thread+768]`=errno、`[TP+56]`=stack guard（见
  `docs/devlogs/2026-10-28-04-M1-TLS布局与门禁修正.md`）
- `tests/integration/02_pure_native.cpp`：不碰 JNI 的 native 函数跑完（含
  mmap/mprotect/munmap、write、getpid/gettid、thunk、exit_group）

**明确不做**：ELF loader、JNI、多线程、VFS、APK、Dynarmic。测试用**裸 blob**（汇编/C `-nostdlib`，不经过 loader）。

### M2 可观测性

**目标**：后面所有调试都靠它。unidbg 最值钱的就是这个。

**交付物**

```
src/runtime/observer/semantic/    # SvcEvent / ModuleEvent / ThreadEvent / MemoryEvent
src/runtime/observer/diagnostic/  # 环形缓冲、丢失计数
src/runtime/backend/unicorn/unicorn_hooks.cpp
tools/trace_viewer/
```

**Gate**

- `02_pure_native` 能输出完整 svc trace
- 未实现的 SVC / 导入符号能 dump guest 调用栈（LR 链）

**明确不做**：全量指令级 trace 默认关闭（`count` 预算 = 每指令 hook，`uc.c:1043`）。

**实测落地**（见 `docs/devlogs/2026-10-28-06-M2设计.md`、`2026-10-28-07-M2结果.md`）：

- `svc.log` 是独立格式（9 列，tab 分隔，args/note 为 JSON），继承 `TraceFormat.md`
  的约定但不复用 `code.log` 的指令行号索引 —— M2 没有指令序号。首列是发布顺序 `id`，
  第二列是调用顺序 `seq`（M3 阻塞 syscall 后才分叉）。
- 事件类型只建 `SvcEvent` + `MemoryEvent`；`ModuleEvent`（M4）、`ThreadEvent`（M3）
  等有生产者时再建。
- gate 拆成两个测试：`02_pure_native`（trace + 内存事件 + 诊断通道）与
  `02_stack_dump`（`io_setup` 未实现 → 4 帧 LR 链逐帧比对）。

### M3 线程

**目标**：pthread 语义跑通，这是所有 JNI/多线程 so 的地基。

**交付物**

```
src/runtime/threads/scheduler.*   # 每 RuntimeThread 一个宿主线程 + engine
src/runtime/threads/futex/        # WAIT/WAKE、WaitQueue、PendingSyscall、阻塞完成式（不重入）
src/runtime/threads/clone/        # CLONE_SETTLS / CLONE_CHILD_CLEARTID
src/runtime/backend/              # 实例级 GuestExecutionLock
```

**Gate**

- `tests/integration/03_pthread_join.cpp`（**裸 blob**）：`pthread_create` + `pthread_join` 返回 0
- N 线程压测：100 次 create/join 无泄漏、无死锁

**明确不做**：warm pool、跨实例调度、fiber。

**实测落地**（见 `docs/devlogs/2026-10-28-08-M3设计.md`、`2026-10-28-09-M3结果.md`）：

- 专用主线程：主 guest 线程有自己的宿主线程，`callFunction` 是请求/响应
- 锁：`execution_mutex`（单核令牌，递归）+ `instance_mutex`（mmap_lock）
- engine 销毁延后到 reaper；退出线程先发 Exited，再 CLEARTID/futex_wake
- Unicorn 的 `timeout` 参数弃用（`_timeout_fn` 与下一轮运行竞态，会把新运行停在 `svc+4`）；
  watchdog 后续自建，ctest `TIMEOUT 60` 兜底
- 真 bionic `pthread_*` 仍未跑：M3 gate 是裸 blob 手写 clone/futex，等最小 bionic 再升格

### M4 loader + 虚拟 bionic

**目标**：加载真实 `.so`，把导入符号接到 host stub。

**交付物**

```
src/runtime/loader/               # ELF、PT_TLS、DT_NEEDED 递归、重定位、符号作用域
src/runtime/loader/reloc/         # RELATIVE / GLOB_DAT / JUMP_SLOT / TLS_*
src/runtime/vfs/                  # 先只做 host_fs_backend
src/runtime/loader/virtual_modules # libc/liblog/libdl/libm 的符号表（不读文件）
```

**Gate**

- `tests/integration/04_so_load.cpp`：加载带 `DT_NEEDED` 的真实 `.so` 并调用函数
- 虚拟模块解析：`write`/`malloc`/`pthread_once` 能落到 host stub

**明确不做**：APK backend、`__tls_get_addr` 的完整 DTV 动态扩展（先做静态 TLS，动态 TLS 等真实目标踩到）。

**测试产物**：`clang --target=aarch64-linux-android31 -fPIC -shared -nostdlib`，导入符号保持 `UND`；`DT_NEEDED` 递归用两个自建 `.so` 互链。不需要 NDK。

**实测落地**（见 `docs/devlogs/2026-10-28-10-M4设计.md`、`2026-10-28-11-M4结果.md`）：

- **TLS 整条推迟**：clang 的 android target 只产 `TLSDESC`（`-mtls-dialect` 不支持），
  静态 TLS 方案作废；遇到 TLS 重定位直接 `Unsupported`。与本节"TLS_*"一条是明确偏差。
- **打包重定位不解析**：`DT_ANDROID_RELA`（APS2）与 `DT_RELR` 检测到即报错，fixture 用
  `-Wl,--pack-dyn-relocs=none`。真实 Android `.so` 默认就是打包格式 —— M6 必做。
- **`pthread_once` 需要 host→guest 回调**，M4 提前落了最小调用桥
  （`HostCallArgs::call_guest`，同 engine 嵌套 `uc_emu_start` + context save/restore，
  上限 32 层）；M5 的 `Call*Method` 直接复用。
- 模块地址固定在 `0x60000000` 起、16 MiB 步进；虚拟模块（libc/liblog/libdl/libm）
  按 soname 精确匹配且**优先于文件系统**。
- 新增 `ModuleEvent`（Load/Needed/Resolve）与 `elf_image_test` 单元测试。

> **2026-10-28 后续修正**：本节的"虚拟 bionic"路线已被
> `docs/devlogs/2026-10-28-12-路线修正-真bionic.md` 取代 —— 改为加载真实 `libc.so`。
> 本节的 loader 骨架、thunk、`call_guest`、`ModuleEvent` 全部保留；虚拟模块表收缩为
> "真机上也不是 libc 提供的"那一小撮（`dl*`、`__system_property_get`、`__loader_*`）。
> 本节保留为历史记录。

### M4.5 loader 补全（真 bionic 第一步）

**目标**：把真 `libc.so` 完整映射并完成所有重定位，**不执行**。

**交付物**

```
src/runtime/loader/reloc/android_reloc.*   # DT_ANDROID_RELA（APS2/SLEB128）
src/runtime/loader/reloc/relr.*            # DT_RELR 位图
src/runtime/loader/tls/                    # PT_TLS 槽、TLS_TPREL/DTPMOD/DTPOFF
src/runtime/loader/tlsdesc.*               # TLSDESC 描述符 + guest resolver 桩页
src/runtime/loader/ifunc.*                 # STT_GNU_IFUNC / R_AARCH64_IRELATIVE
```

**Gate** `04b_libc_map`：

- 加载 `DuckEmu/bionic/{libc,libm,libdl}.so`，重定位全成功、无未解析符号
- `libsgmainso`（section header 损坏）能只用 program header 正常映射
- ModuleEvent 记录真实依赖边

**搬运来源**：`DuckDroid/code/engine/loader/{elf_loader,tls_layout}.*`

**明确不做**：不跑 libc（那是 M4.6）。

### M4.6 真 bionic（跑起来）

**目标**：真 libc 的 `preinit`/init_array 执行完，malloc/pthread/文件 IO 可用。

**交付物（按子步骤）**

1. `src/runtime/svc/`：搬 `os_state` 的 128 个 syscall case（arm64 语义）
2. `src/runtime/vfs/`：`/proc/self/{maps,status}`、只读文件 mmap
3. `src/runtime/loader/bionic/`：`libc_shared_globals`（偏移按 ROM objdump 核对）、
   `__loader_*` 绑定、`__libc_preinit`
4. `src/runtime/memory/`：scudo 预留（8.25 GiB `PROT_NONE|MAP_NORESERVE` 只登记、
   按需物化）、`1<<56`/`2<<56` TBI alias
5. `src/runtime/threads/`：clone/futex 对齐 bionic，真 `pthread_create/join`

**Gate** `04c_bionic`：

- 真 libc 加载 + preinit 完成；`malloc/calloc/free` 走真 scudo
- 真 `pthread_create/join` 计数正确，每线程 errno/TLS 隔离
- `libeleven` 的 `JNI_OnLoad` 之前部分能跑（JNI 本体是 M5）

**搬运来源**：`DuckDroid/code/engine/os/os_state.*`、
`runtime/runtime_instance.cpp`、`runtime/address_space.*`

**明确不做**：JNI（M5）、信号投递（只留 no-op）、`dlclose` 卸载。
